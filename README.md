# Yohaku · 余白

Приложение для iPhone, iPad и Mac: рукописные тетради, бесконечный холст, Markdown и помощник по выделенному фрагменту. Рабочее название — **Yohaku** («свободное пространство»). Версия для Mac работает через Mac Catalyst и использует тот же формат документов, что iOS.

## Запуск

Требования: Xcode с iOS 26/macOS 26 SDK, Swift 6.2+, XcodeGen. Основная мобильная аппаратная цель — iPad на M-серии. Для симулятора локальная MLX-генерация не является доказательством производительности на устройстве.

```sh
xcodegen generate
open Yohaku.xcodeproj
```

Схема приложения — `Yohaku`, тестов — `YohakuTests`. В Xcode она предлагает iPhone/iPad Simulator и `My Mac (Mac Catalyst)`. Источник конфигурации проекта — `project.yml`. При изменении Signing в Xcode перенесите выбранную Team и bundle ID в этот файл до следующей генерации.

Для CLI:

```sh
# iPhone или iPad Simulator
xcodebuildmcp simulator build-and-run --project-path "$PWD/Yohaku.xcodeproj" --scheme Yohaku --simulator-id SIMULATOR_UUID --derived-data-path /tmp/yohaku-derived
xcodebuildmcp simulator test --project-path "$PWD/Yohaku.xcodeproj" --scheme Yohaku --simulator-id SIMULATOR_UUID --derived-data-path /tmp/yohaku-derived

# Mac Catalyst
xcodebuildmcp macos build-and-run --project-path "$PWD/Yohaku.xcodeproj" --scheme Yohaku --derived-data-path /tmp/yohaku-mac-derived
```

AnyLanguageModel закреплён на конкретном commit; локальный пакет `StudyIntelligence` включает trait `MLX`. Файлы `Package.resolved` фиксируют транзитивные версии. Сборка требует доступа к GitHub при отсутствии кэша.

## Работа с приложением

- При первом запуске Yohaku сразу открывает собственную папку в iCloud Drive и создаёт в ней два стартовых документа. При обновлении старое локальное хранилище копируется туда, если облачная папка ещё пуста; локальная копия остаётся резервной. Если iCloud Drive недоступен, приложение явно сообщает об этом и временно работает локально. Через меню хранилища можно вернуться в iCloud или выбрать другую папку вручную.
- В дереве папок доступно контекстное меню: создание, переименование/перемещение, открытие рядом и удаление в локальную корзину.
- Табы сохраняют порядок, выбранную страницу, масштаб и позицию курсора. Контекстное меню таба позволяет открыть документ рядом или переместить таб в начало.
- В тетради миниатюры слева переключают страницы. Контекстное меню миниатюры дублирует, переставляет или удаляет страницу.
- Apple Pencil рисует; палец перемещает лист. «Объекты» включает выбор и перетаскивание карточек; кнопки масштабирования меняют выбранный объект, повторное нажатие на ссылку открывает её.
- «Бумага» меняет фон, шаг и цвет разлиновки. Учебная клетка содержит пунктирные направляющие.
- Кнопка выделения включает прямоугольный выбор фрагмента для агента. Перед отправкой видны снимок и поле вопроса. Стандартное лассо PencilKit управляет рукописью.
- Markdown использует TextKit 2: активный абзац раскрывает синтаксис, остальной текст форматируется. `[[текст]]` показывает фильтруемый autocomplete заметок и папок; выбор превращается в обычную относительную Markdown-ссылку. Кавычки, обратные кавычки и `()[]{}` закрываются автоматически. Режим исходника доступен в панели редактора. Поддерживаются локальные изображения и относительные ссылки.
- Ответ помощника можно сохранить в новую или существующую Markdown-заметку со ссылкой на источник. Предложения инструментов применяются только кнопкой «Применить».

## Модели

Исправление SmolVLM, профиль для iPad с 4 ГБ и результаты реального прогона: [smolvlm-fix.md](docs/smolvlm-fix.md).

В настройках выбирается локальный MLX, OpenAI-совместимый API, Codex или сервер Sloppy. Переключение не происходит автоматически.

- Локально: открыть «Каталог Hugging Face и подбор». Вкладка «Каталог HF» ищет по всему Hub, без фиксированного списка авторов/моделей; «Для устройства» оценивает живую выдачу по RAM, свободному месту, формату и архитектуре. Можно также вставить ID или ссылку на модель вручную.
- Перед загрузкой показываются размер файлов, оценка RAM, поддержка изображений и причины несовместимости. Для приватных/gated-репозиториев поддерживается read token в Keychain; необходимые разрешения оформляются на сайте Hugging Face.
- OpenAI / совместимый API: указать endpoint с `/v1`, model ID и сохранить API-ключ в Keychain.
- Codex: нажать «Войти в Codex», ввести показанный device code на открывшейся странице авторизации и вернуться в Yohaku. После подтверждения загрузить каталог и выбрать модель. Сессия и refresh token хранятся только в Keychain устройства.
- Сервер Sloppy: указать URL и токен, сохранить токен в Keychain, загрузить модели и выбрать нужную. Сервер должен поддерживать `POST /v1/providers/inference` (Sloppy inference v1). Каталог старого сервера может открываться, но генерация без обновления вернёт HTTP 404.
- API-ключи привязаны к адресу и провайдеру. Старый ключ OpenAI переносится в привязанную запись Keychain; настройки и скачанные модели сохраняются.
- Потоковые ответы Codex и Sloppy поддерживают изображения и инструменты `notes`; предлагаемые изменения применяются только после подтверждения в Yohaku. Ключи и OAuth-токены не записываются в хранилище заметок.
- Каталог может показывать любые форматы, но локальная загрузка/запуск сейчас рассчитаны на MLX safetensors с поддерживаемым адаптером. Наличие модели на Hub не означает совместимость с приложением. Старые скачанные модели и незавершённые загрузки сохраняются.
- До загрузки в память выполняется консервативная оценка по размеру весов. Она не заменяет испытания на конкретном устройстве.
- При уходе в фон запрос останавливается, частичный ответ сохраняется. Запрос можно повторить после возврата.

## Архитектура и формат

`Packages/StudyKit`:

- `StudyCore`: `VaultStore`, `DocumentSession`, версии документов, предложения изменений, ссылки, модель страниц и объектов.
- `StudyCanvas`: общий `PencilSurfaceView`, адаптер для SwiftUI и независимый композитный `CanvasRenderer`.

`Packages/StudyIntelligence`: AnyLanguageModel, загрузка моделей, Keychain, агентная сессия и инструмент `notes`. Код не зависит от серверного процесса Sloppy.

`App`: оболочка SwiftUI, дерево файлов, табы, редакторы, чат и настройки.

Файлы:

```text
Хранилище/
  日本語/
    Грамматика.md
    Практика.studycanvas/
      manifest.json
      assets/<UUID>.drawing
      assets/<UUID>.png
  Вложения/<UUID>.png
  .workspace/
    vault-id
    records/<hash пути>.json
    trash/<UUID>/...
```

Markdown остаётся UTF-8 текстом. Его служебная запись содержит идентификатор и чат. Канвас — пакет с JSON schemaVersion=1 и неизменяемыми файлами рисунков/изображений. Манифест записывается последним; неиспользуемые файлы рисунков удаляются после успешного сохранения с учётом Undo/Redo.

Infinity хранит целые штрихи в областях; индекс учитывает полные границы, в том числе пересечение нескольких областей. Загрузка ограничена окном просмотра с запасом. Перенос рабочего окна после панорамирования сохраняет мировые координаты.

Операции сериализуются в `VaultStore` и координируются через `NSFileCoordinator`. Состояние документа общее для его открытых редакторов. Ревизия файла защищает сохранение; отдельная ревизия содержимого позволяет продолжать чат без устаревания предложений. Внешнее изменение содержимого делает старое предложение неприменимым.

Версии iCloud сначала копируются в отдельные видимые документы; только после сохранения всех копий конфликт системных версий помечается разрешённым. Собственного сервера синхронизации или слияния штрихов между устройствами нет.

## Проверки

```sh
CLANG_MODULE_CACHE_PATH=/tmp/study-module-cache \
SWIFTPM_MODULECACHE_OVERRIDE=/tmp/study-module-cache \
swift test --package-path Packages/StudyKit --scratch-path /tmp/study-core-build --disable-sandbox
```

Файловые тесты требуют доступа к системной службе NSFileCoordinator. В ограниченной песочнице она может отклонить операцию даже для временного файла.

Схема Yohaku запускает 5 iPad unit-тестов и один сквозной UI-тест: композитный снимок, выборочная загрузка областей, Markdown, отклонение устаревших правок, инструменты AnyLanguageModel и выделение области для агента. Проверка Apple Pencil, IME, iCloud между устройствами и качества модели требует реального оборудования/аккаунта. Текущие доказательства и ограничения — в `docs/validation.md`.

## Сравнительный прототип AdaEngine

Отдельный проект: `Prototypes/AdaCanvas/AdaCanvasProbe.xcodeproj`; генерация — `xcodegen generate --spec Prototypes/AdaCanvas/project.yml`.

Он использует `AdaUI.UIKitViewRepresentable` и **тот же** `StudyCanvas.PencilSurfaceView`. Исходники AdaEngine и Sloppy не изменяются. Путь к AdaEngine предполагает соседний каталог `../AdaEngine` относительно Workspace. Основное приложение не линкует движок.

Сведения о переиспользовании — в `THIRD_PARTY_NOTICES.md`.

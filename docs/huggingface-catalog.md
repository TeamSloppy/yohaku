# Каталог Hugging Face и профиль iPad

Путь в приложении: **Модели и настройки → Каталог Hugging Face и подбор**.

## Два режима

- **Каталог HF:** поиск по названию/автору/ID во всём каталоге, пагинация; фильтры MLX и задачи необязательны. Нет списка разрешённых model ID.
- **Для этого iPad:** живая выдача MLX с серверным фильтром числа параметров (до 1B для ≤4 ГБ RAM, до 3B для больших профилей). Для результатов скачиваются только метаданные и `config.json`, затем сравниваются реальные размеры файлов и поддержка архитектуры. Это предварительный фильтр; ограничение можно снять в полном каталоге.

Подбор проверяет до трёх страниц за один запуск; доступно продолжение. Метаданные загружаются максимум тремя параллельными запросами. Смена запроса отменяет старую работу, запоздалые ответы не подменяют новую выдачу. Поиск не скачивает веса.

## Характеристики

`DeviceModelProfile` читает hardware identifier, физическую RAM, доступную процессу память, свободное место, версию системы и имя Metal GPU. iPad8,1…iPad8,8 подписываются как iPad Pro 2018 с A12X. RAM не назначается по названию модели: варианты с разным объёмом памяти определяются измерением.

В симуляторе явно показывается, что используется условный профиль 4 ГБ; он не выдаётся за характеристики физического iPad. Модель устройства и RAM не отправляются в Hub — только поисковые фильтры.

Оценка RAM = `2 × bytes(weights) + 512 MiB`. Это консервативная эвристика, общая с текущим admission budget, а не замер пика конкретной архитектуры. Метки:

- кандидат по формату, адаптеру и оценке RAM;
- мало запаса памяти;
- не проходит бюджет RAM/накопителя;
- неподдерживаемый формат/архитектура;
- недостаточно данных для оценки.

Поддержка архитектур берётся из снимка реестров закреплённой mlx-swift-lm 2.31.3; проверка не создаёт модель и не выделяет память под её веса. Новый `model_type` остаётся видимым в полном каталоге с объяснением. Наличие адаптера не гарантирует скорость, качество японского и поддержку всех вариантов checkpoint.

## Доступ и загрузки

Публичный поиск работает без аккаунта. Опциональный HF read token хранится отдельно от ключа сетевого AI-провайдера в Keychain. Для gated-моделей приложение предлагает открыть страницу и самостоятельно получить доступ. Token отправляется только на `https://huggingface.co`; при redirect на CDN заголовок Authorization удаляется.

Загрузка использует ту же карточку и фиксированный SHA ревизии. Старые `.download.json` совместимы; при возобновлении проверяется размер готового файла. Каталог не смешивает разные наборы весов одного репозитория. Нужен MLX checkpoint с конфигурацией и safetensors в корне; GGUF/ONNX/PyTorch показываются с причиной, почему нужен другой движок или экспорт.

## Проверка

- 14 unit/integration-тестов YohakuTests прошли, включая пять проверок каталога: произвольные model ID, оценки памяти, неизвестные размеры/архитектуры, URL/пагинация, HTTP metadata/auth errors, redirects и совместимость старого download manifest.
- UI-тест открыл каталог, переключил полный режим, проверил фильтр MLX и экран read token; прошёл.
- `Validation/SmolProbe --catalog` обратился к живому Hub без токена: получено 30 моделей и ссылка на следующую страницу, проверены первые 12. В выдаче были разные авторы и семейства; результаты сохранены в `huggingface-catalog-probe.txt`. Веса не скачивались.
- Подбор в этой CLI-проверке использовал явный тестовый профиль iPad Pro 2018 / 4 ГБ, а не измерение подключённого устройства. На самом iPad профиль считывается приложением.

Источники: [Hub API](https://huggingface.co/docs/hub/api), [User access tokens](https://huggingface.co/docs/hub/security-tokens), [iPad Pro 11″ 2018](https://support.apple.com/en-ie/111974).
